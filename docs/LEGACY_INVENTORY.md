## 1. What the old project is

- Swift / SwiftUI app named "Trace" (`com.inoxixi.trace`), iOS 26 minimum, about 67 Swift files / 11.2k lines.
- It is the native rewrite of the Flutter app FogMap (see its `MIGRATION_PLAN.md`). The product model is **manual START/STOP track sessions** plus a fog-of-war "discovery" view. That model is overturned by D1 (all-day recording) and D6 (diary, not fog).
- Xcode project is generated by `Tools/generate_project.rb`. It has **one third-party dependency: GRDB 7.10** (SQLite).
- `docs/superpowers/` holds the old design specs and plans. The most relevant is `2026-09-15-trace-stabilization-design.md`.

## 3. TraceStabilizer in detail

### 3.1 What it does

`TraceStabilizer` is a value-type (`struct`) state machine. For each incoming sample it gives every canonical point a `TraceDecision`:

- `confirmed`: part of the drawn route
- `provisional`: still undecided (drawn faintly, can be revised later)
- `suppressed`: hidden (drift, jump, invalid data)

It also keeps a coarse `MotionState` (`moving` / `stationary` / `uncertain`). Its main mechanisms are:

1. **Stationary-cloud detection** (`stationaryClusterEnding`). It looks for a window of 5–8 points and 20–30 s whose points all lie within an accuracy-scaled radius of an accuracy-weighted anchor, with small net displacement, a high path-to-net ("jitter") ratio and no speed evidence. The cluster is suppressed and frozen at the anchor.
2. **Hysteresis for leaving a stay** (`progressesFromStationary`). Three coherent steps away from the anchor are needed before movement is confirmed again.
3. **Movement confirmation** (`isMovementStep`, `coherentMovement`). A run of coherent forward steps is promoted from provisional to confirmed.
4. **Isolated-jump rejection** (`isIsolatedReversal`). A 3-point out-and-back is suppressed unless speed, course and accuracy show a real U-turn.
5. **Multi-point excursion suppression** (`TraceExcursionDetector`). A short, weak-accuracy run that leaves the confirmed corridor and comes back is suppressed. Strong, speed-supported loops are kept.
6. **Large-gap boundary**. When two samples are more than 180 s apart, no segment or confirmation crosses the gap.
7. **Display smoothing** (`smoothConfirmedPoints`). A 3-point, accuracy- and time-weighted average is applied to confirmed vertices, always computed from the canonical coordinates. Real corners (both legs ≥ threshold, heading change ≥ threshold, good accuracy) are left alone.
8. **Metrics**: confirmed distance, raw distance, discarded provisional distance, excursion counters, and `algorithmVersion` (currently 2) for rebuilding derived data.

The design keeps **raw points immutable and decisions in a derived layer**, with deterministic replay and versioned rebuilds. That matches P5 well.

### 3.2 Inputs and outputs

| | Type | Notes |
|---|---|---|
| Input | `RecordedLocation` | lat, lon, altitude?, horizontalAccuracy, verticalAccuracy?, speed?, course?, timestamp. **No timezone and no source field** (F1 requires both) |
| Input | `TraceStabilizerConfiguration` | 30 tuning constants plus `algorithmVersion` |
| Entry points | `process(_:includeDisplay:)`, `finish()`, `static replay(_:)`, `static resuming(_:)` | `process` returns a proposal (`TraceStabilizerTransition`). The caller adopts `next` only after its database write succeeds |
| Output | `StabilizedTraceUpdate` | state, `changedPoints: [TracePointUpdate]` (decision + display coordinate per timestamp), distances and counters, `confirmedSegments` / `provisionalSegments` (`[[TraceCoordinate]]`), stationary anchor |

### 3.3 Dependencies

- **Frameworks**: Foundation and CoreLocation only (`CLLocation.distance(from:)`, CL typealiases). There is no MapKit, GRDB or UI dependency.
- **Old modules**: `RecordedLocation` (Location/), and `MotionState` / `TraceDecision` / `TraceCoordinate` / `MapDisplayTrace` / `StabilizedTraceUpdate` (the TraceProcessing types themselves). It is otherwise self-contained.
- **Callers in the old app**: `RecordingEngine` (live `process`, `resuming`), `GRDBTrackRepository` + `TraceRebuilder` (`replay`, persisted decisions).

### 3.5 Fit with the new contract

| Topic | Old behaviour | New requirement | Consequence |
|---|---|---|---|
| Session model | `finish()` closes a START/STOP session. Unresolved provisional points are suppressed at the session end | All-day recording (D1). There is no session end | `finish()` needs a new trigger, such as a long gap, a day boundary or a CLVisit, or it must be dropped. This is a design decision for the Design stage, not for the migration task |
| Memory | `locations` holds the **whole session** in memory | All-day recording, and one year of data must stay smooth (F7) | The working set must be bounded (see §4.2) |
| Stays | Suppresses drift into an anchor | F3 says CLVisit comes first | The stabilizer becomes the fallback and fine-grained layer under CLVisit. How the two combine belongs to Design |
| Smoothing | 3-point weighted average on vertices | D22 / F7: smooth **curves** in the display layer, without rounding off sharp turns | Corner preservation and canonical-coordinate smoothing can be reused. Curve generation (spline) is new work in the renderer |
| Poor-accuracy points | Suppressed, but the raw point is kept | F1: keep and flag them as hints (e.g. underground gaps) | Compatible, as long as the raw store keeps them. The old `DefaultLocationFilter` drops them *before* storage, which conflicts with F1 (see §5) |

## 4. Known issues: where they come from

### 4.1 Track crossing and overlap

The old code has no `crossing` / `overlap` fix or issue marker. Two places in the code produce visible crossing and overlap artefacts. **I inferred these locations by reading the code; I could not reproduce them here.**

1. **Semi-transparent per-segment overlays.** `Map/MapCoordinator.swift:159-189` adds one `MKPolyline` per confirmed or provisional segment. Each has its own renderer, and the opacities come from `Map/RouteTheme.swift:64-85` (historical 0.65, revisit 0.55, provisional 0.35). Where segments, days or repeated routes cross or overlap, the alpha stacks into darker blotches. The old design accepts this explicitly in `docs/superpowers/specs/2026-09-13-trace-ground-width-route-rendering-design.md:80`.
2. **Ground-width line scaling.** `RouteTheme.swift:88-123` (`GroundWidthLineScale`, 20 m ground width clamped to 2.5–8 pt) and `MapCoordinator.swift:268-293`. At street scale, parallel or back-and-forth passes merge into thick overlapping bands. F7 requires a **screen-pixel** line width instead.
3. Related: segments start and end at every suppressed point or gap of more than 180 s (`TraceStabilizer.swift:1391-1462` `displayTrace`), so one walk can become many short overlapping polylines whose round caps stack.
4. The fog import path had "ladder" artefacts, fixed in `c48968b` / `85f7439` (`Map/ImportedCoverageVectorizer.swift`). That path is not relevant to the new app.

### 4.2 O(n) scans and copies per sample

The design spec says "bounded window work per sample" (`stabilization-design.md:119`). The bookkeeping is bounded, but several steps still touch the whole history on **every** live sample:

| Location | What happens | Cost per sample |
|---|---|---|
| `TraceStabilizer.swift:126-127` (`process`) | `var nextLocations = locations; append(...)`: copy-on-write copies the full array, because `self` still holds a reference to it | O(n) copy |
| `TraceStabilizer.swift:375-384` (`derive`) | `points = initial.points` and then mutation: full copy of `derivedPoints` | O(n) copy |
| `TraceStabilizer.swift:726-731` | `decisions: points.map { $0.decision }` passed to `TraceExcursionDetector.analyze`: a full map, even though the scan itself starts at `scanFrom` | O(n) allocation |
| `TraceStabilizer.swift:1391-1462` (`displayTrace`) via `makeUpdate` (`:302-309`) | Rebuilds **all** confirmed and provisional segments from index 0 whenever `includeDisplay == true` (the foreground case) | O(n) scan + allocation |
| `TraceStabilizer.swift:152-157` | Each transition builds a new `TraceStabilizer` value holding both full arrays | Keeps the copies above alive until adoption |
| `Map/MapCoordinator.swift:116-117, 140, 159-189` | Removes and re-adds every overlay of a route on each refresh | O(n) per refresh on the main thread |
| `Database/Repositories/GRDBTrackRepository.swift:160-163, 460` | `replay` loads every point of a track into memory and replays it in one pass | O(n) memory (acceptable for rebuilds, not for live use) |

With all-day recording, n grows without limit, and a session no longer resets it. That makes these costs much worse than they were in the old app.

## 5. Other findings relevant to the new contract

- `Location/LocationFilter.swift:16-22` (`DefaultLocationFilter`) **drops** samples with accuracy > 100 m, closer than 3 m, or implying speed > 300 km/h. This conflicts with F1 ("精度很差的点不丢弃，标记后保留").
- `Location/CoreLocationClient.swift:90-110` starts `CLServiceSession` + `CLBackgroundActivitySession` + `CLLocationUpdate.liveUpdates(.otherNavigation)` with **When-In-Use** authorization. This is a good reference for spike S1, but Trace Notes needs Always authorization and must keep the session alive while paused.
- The old Info.plist only had the When-In-Use description and a temporary-precise-location purpose. Trace Notes adds Always and Motion descriptions.
- GRDB is the only third-party dependency. Under AGENTS.md / PRODUCT §5, keeping it would need a reported, concrete justification. That decision belongs to the Design stage.
